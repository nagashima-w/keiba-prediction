## 3. 地方: 取得経路の確定

### 3.1 ページ構造の観測(#3)

`GET https://nar.netkeiba.com/odds/index.html?type=b8&race_id={race_id}` の静的HTMLには、
3連複(#13)と**同一のJS関数名**(`onchange="view_3odds_normal()"`)を持つ単一の軸馬選択プルダウン
(`<select id="list_select_horse">`)が存在する。ページ読み込み時点では軸馬1固定の内容が表示される
(`<option value="1" selected="selected">`)。

- ページ内の`td.Odds[id^="chk_"][id*="_b8_c0_"]`は**110件**(=P(11,2)=11×10。全体P(12,3)=1320の一部)
- IDは3つの馬番を持つ(例`chk_..._b8_c0_1_2_3`)。**先頭の馬番はすべて`1`**(軸馬1固定であることの
  直接確認。`grep`で全110件の先頭数字が一意に`1`であることを確認済み)

軸馬切替のJS実装(`$('#list_select_horse').val()`を`jiku`パラメータとしてAJAX GET)は3連複(#13)と
**完全に同一のコードパターン**だった:

```js
umaban = $('#list_select_horse').val();
var url = "../odds/odds_get_form.html?type=b8&race_id=202654071210&jiku=" + umaban;
```

### 3.2 軸の意味: 「1着固定」であり、3連複の「含む」とは異なる(変数を1つだけ変える検証)

3連複(#13)の`jiku=k`は「kを**含む**全トリオ」を返す(順序を持たない組合せ)。三連単でも同じ意味
(「kを含む全順列」)なのか、それとも「kが**1着**の全順列」という異なる意味なのかは、事前には
判別できなかった。

**検証**: `jiku=2`のフラグメント(#4)を取得し、返る110件の先頭馬番を確認したところ、**全件が`2`**
だった(3連複であれば「2を含む」だけで先頭固定にはならないため、この結果は「1着固定」仮説を支持し、
「含む」仮説を棄却する)。

再現コマンド(AC-A7):

```
grep -o 'chk_[^"]*_b8_c0_[0-9]*_[0-9]*_[0-9]*' fixtures/nar_odds_b8_jiku2_202654071210.html \
  | sed -E 's/.*_b8_c0_([0-9]+)_.*/\1/' | sort -u
→ 2 (1行のみ。全110件の先頭馬番が2で統一されている)
```

さらに`jiku=5`(#5)でも同様に全110件の先頭馬番が`5`で統一されていることを確認した(§5.1の
払戻突合で使用)。

**結論: 三連単の軸は「1着を固定する」という意味であり、3連複の「(順不同で)含む」とは異なる。**
これは3連単が着順を持つ券種であることと整合する(3連複は着順を問わないため「含む」という緩い
条件で十分だが、三連単は「1着が誰か」という強い条件を持つ)。

### 3.3 全組合せに必要なリクエスト数(AC-A2): **n回**。3連複の n-2 とは異なる

3連複(#13)は「トリオの最小馬番は必ずn-2以下になる」という数学的性質により、軸1〜(n-2)を叩けば
全組合せをカバーできた。しかし三連単の軸は「1着固定」であり、**どの馬番も1着になりうる**ため、
この性質は成り立たない。1着が軸馬番と一致する順列群(P(n-1,2)件)は軸馬番ごとに互いに素
(先頭馬番が異なるため重複なし)であり、全軸馬番1〜nを合計すると:

```
n × P(n-1,2) = n × (n-1) × (n-2) = P(n,3)
```

となり、**ちょうど全組合せをカバーするために軸1〜nの全n回が必要**(n-2回や(n-2)回では、
軸(n-1)・軸nが1着になる順列〈それぞれP(n-1,2)件、合計2×P(n-1,2)件〉が欠落する)。

- 12頭のレースなら**12リクエスト**、16頭なら**16リクエスト**必要(3連複の同条件では10回・14回)
- 本タスクでは軸1(#3、既定表示)・軸2(#4)・軸5(#5)の**3軸のみ**取得し、残り9軸(3・4・6〜12)は
  取得していない(AC-A2の要求どおり、全件取得はせず構造と式の確定に留めた)
- 3軸で得られた330件(=110×3)はいずれも重複がない(先頭馬番が1・2・5で互いに異なるため)ことを
  実データで確認済み

### 3.4 軸馬選択プルダウンの選択肢数(観測値)

`<select id="list_select_horse">`内の`<option value="N">`は**12件**(1〜12。3連複〈#13〉と同じ
「全頭数ぶんの選択肢」という観測値)。これは§3.3の「導出値n」と一致する(3連複では観測値〈1〜n〉と
導出値〈n-2〉が異なっていたが、三連単では両方ともnで一致する)。

## 5. AC-A3: 三連単のキーが着順どおりであることの証拠

### 5.1(a) 同じ3頭の異なる並びが別エントリとして異なる値を持つこと(無条件expect)

中央16頭・確定オッズ(3360件)を全件走査し、以下を確認した(`trifecta-odds-fixtures.test.ts`
「中央」describeで固定):

- **完全反転(1着↔3着を入れ替え、2着はそのまま)のペアが存在し、かつ値が異なる件数**:
  3360件中**3356件**が異なる値を持ち、**4件(=2組)**は値が一致していた(いずれも人気が3000番台の
  超高オッズ〈37,065.1・17,229.0〉同士で、丸め表示上たまたま一致しただけであり、`人気`
  〈3番目の要素〉は異なる値を持つことを確認済み。例: `"161003"`=`['37,065.1','0.0','3119']` と
  `"031016"`=`['37,065.1','0.0','3117']`)
- **同じ3頭の6通りの並びがすべて揃っている組合せ数**: C(16,3)=560通り全件で6通りの並びが揃っており
  (P(16,3)=3360=560×6と整合)、そのうち**547通り**は6つの値が完全に相異なり、**13通り**は
  6値の中に重複がある(上記と同じ理由。稀にしか売れない超高オッズの組で丸め表示が一致する)

    種類数だけを見るとキャップ値は「39分の1種類」で少数に見えるが、**エントリ件数で見ると
    その1種類がほぼ8割を占める**という逆の構図になっている
  - **`人気`(3番目の要素)は3360件全件が相異なる値を持つ**(重複なし。オッズが同じキャップ値に
