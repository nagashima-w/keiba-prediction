## 8. #258 / #35 系列への含意(判断材料)

1. **左右・当距離・最高タイムは、既存の戦績取得(馬ごとに 1 リクエスト)から再構成できる見込みがある**(33 頭・3 レースで、7 列 × 33 頭のうち不一致は姫路の 2 行の 1 件だけ。ただし海外の走の扱いは標本2 で確定したもので、全成績・左右の 3 列の標本2 の一致は独立した検証ではない。`中` の規則は未検証)。ZIP を新しい情報源にしなくても、戦績の行+(競馬場,種別,距離)→回りの表で足りる可能性がある。
2. 回りの表は ZIP の `racelist` から作れる(2 か月で 84 通り。大井 1650m が左)。表の元データとしての ZIP の価値は残る。netkeiba のレースページの `(右)/(左)` からも作れるが、過去の行には無い。
3. **ZIP は検証用の基準としても使える**: 発走前の成績(6.5)なので、再構成の正誤を測れる。
4. 食い違いは**値そのもの**にもある(6.2・6.3: 体重増減の空欄と `0`、人気の同率の順、頭数の数え方)。「同じレースの情報が食い違うことは基本ありえない」という前提は、**表記の違いについては成り立つが、値については 3 種類で成り立たなかった**。人気の同率の順は、どちらが公式かを確かめていない。#65 のルール(a)(地方は keiba.go.jp を正とする)が効く論点は、少なくともこの 3 つ。
5. ZIP の `頭数` を使うなら、取消・除外の馬を含む(6.3)。馬体重が `－` の行(取消)、および着順が空で馬体重が数字・人気なしの行(除外、3 レースの標本)を除く規則が要る。

- `<ZIP を展開した親>` は `<親>/202607/extracted/202607_{racelist,horselist,payback}.csv` の形(9 月も同様)。
- 個別に実行する場合は、`scripts/keibago-66/` の `check_ids.py`・`compare_races.py`・`compare_history_rows.py`・`reconstruct_history.py`・`check_blank_rank.py`・`turn_table.py`・`zip_stats.py`・`netkeiba_columns.py` を、それぞれ `--help` の引数で。
- 入力の同一性は `summary.json` の `入力` に CSV の SHA-256 の先頭 16 桁で記録した。
- `fetch_netkeiba.py --dry-run` は、リクエストを送らずに取得する URL を出す。段階A の 20 件は、台帳の URL の集合と一致することを確認した。
- 400 を返した馬の再試行は、取得スクリプトには組み込んでおらず、手で 1 回だけ再実行した(`--retry-horse <id>` で指定できる)。
- **文中で「手集計」と書いた数値**(コミット済みのスクリプトの出力には無い。調査中に使い捨てのスクリプトまたは目視で確かめた値): 標本1 の「地方のみ」の左 13/20・右 9/20、姫路 1400m を右とした手計算、騎手名の 5 件、着順が空で体重が数字・人気なしの 82 レース(159 行)、頭数が食い違う 4 レースの空欄の行の体重、金沢 3R の単勝オッズ 13.1、標本2 の海外 4 行の内訳(ソウル・メイダン・キングアブドゥル)と海外の行を持つ 2 頭、台帳から測った実際の間隔(最小 2.03 秒・中央値 2.23 秒)。再現するには、入力を同じ場所に置いて同様の集計を書く必要がある。
