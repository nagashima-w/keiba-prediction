# LLM に渡す prior を学習モデルに入れ替える試算(Issue #662 段階 1)

本番のコード(`packages/core/src`・`cloud/src`)は変えていない。計算し直しの道具(`scripts/allocation-dataset.ts` の `replayedBets`・`adjustProb`)と、このフォルダの道具だけで比べた。

## 結論(決め方の規則を機械的に当てはめた結果)

**規則を満たす候補はなかった。段階 2 には進まない。**

規則(試算の前に固定。Issue #662): `lr50`・`lr100` のうち、中央 500 レースで (1) 回収率が cur 以上(点推定)、(2) 見込み/実が cur より 1 に近い、を両方満たすものがあれば進む。cur は回収率 96.6%・見込み/実 1.11。

| 候補 | 中央の回収率 | 中央の見込み/実 | (1) | (2) |
|---|---|---|---|---|
| lr50 | 88.8% | 1.08 | × | ○ |
| lr100 | 92.7% | 1.34 | × | × |

- `lr50` は見込み/実だけ良くなったが、回収率は 7.8pt 下がった。cur との差の対ブートストラップ 95% 区間は −35.1%〜+16.4%(差が正になった割合 29.3%)で、小さな差も大きな差も区間に入る。
- 判定は 500 レースの合計の点推定で、少ない的中が回収率を大きく動かす標本(例: cur の中央の馬単は 17 点・的中 2 点で回収率 455.8%。券種別の表を参照)。回収率の 95% 区間は cur 自身が 66.6%〜130.2%。

### 規則の外に書いておく事実(段階 2 の形はユーザーと決める)

学習モデルは、同じ入力の元の prior より良く、LLM の補正後(cur)より「馬単位の 3着内率」は良いが、配分の回収率は cur に届かなかった。

- 学習モデル `lr50` は、prior を寄せただけの `prior50`(書き出しの prior)・`rprior50`(今のコードで作り直した prior)より、中央の回収率(88.8% 対 82.9%・85.5%)も見込み/実(1.08 対 1.27・1.23)も良い。
- 馬単位の対数損失(中央・全馬 6585 頭)は、`lr50` 0.4363、`cur` 0.4478、`rprior50` 0.4378、`prior50` 0.4511。lr50 が一番小さいが、rprior50 との差は 0.0015 と小さい。
- それでも回収率は cur(96.6%)より低い。cur は LLM が馬ごとに足した情報(補正)が配分の当たり方に効いている可能性があるが、この試算だけでは確かめられない(標本の揺れと区別がつかない)。
- 「prior(書き出し・当時)」と「prior(replay・今のコード)」は別物。対数損失は 0.4990 対 0.4657(寄せる前の素の確率・中央)で、今のコードで作り直した prior のほうが良い。これは「LLM に渡す prior を今のコードで作った値に更新する」だけでも効く可能性を示すが、cur の回収率はその当時の prior を使った LLM の出力で測っている点が違う(別の比較になる)。

## 材料と手順

- 材料: 本番の配分の書き出し(2026-10-27 時点、931 行)のうち、配分の記録がある 545 行(中央 500・地方 45。開催日 2026-09-03〜10-25)。リポジトリには入れない。
- **係数は保留を捨てて学び直したもの。試算の 545 レースは学習に使っていない。** 本番の `stat-shadow-coef.ts` の係数は保留(2026-08〜10)を開いた学習なので、そのままでは 545 レースが学習に入ってしまう。`fit_pre_holdout.py` で 2025-02〜2026-07(5225 レース・72083 頭)だけで学び直した(オッズなし版。前処理・学習は `scripts/stat-model-649/export_coef.py` と同じ)。標準化した係数は、`fit.py`(`--open-holdout` なし)が書いた `importance.json` の `lr_noodds` と、最大差 0.0 で一致した(=同じ学習の再現)。
- 学習モデルの入力は、`replay.ndjson.gz`(#649 段階 1 の出力。今のコードで prior と寄与を作り直したもの)の該当レース(race_id・馬番で引く)。本番の R2 の寄与(当時のコードで作った版)は参考の `lr50r2` だけに使った。中央 500 レースは全部 replay にあった。replay に無い馬は取消の 12 頭(12 レース)で、その馬は adjusted_prob のまま(買い目に入らない)。
- 特徴量の作り方(`lr.ts` の `lrTop3`)は本番 `computeShadowProbs` のオッズなし版と同じで、本番の係数を入れたときに 1e-12 以内で一致することをテストで固定した(`scripts/test/prior-swap-662.test.ts`)。
- 地方 45 レースは、学習が中央だけなので `lr`・`rprior` 系でも cur と同じ確率のまま(表では別枠の参考)。`prior50`・`prior100` は書き出しの prior があるので地方にも当てた。判定は中央だけ。
- 候補(`replay.ts` の `CANDIDATES`。結果を見る前に固定): `cur`(補正後を 0.5 寄せ)・`prior50`/`prior100`(書き出しの prior を 0.5 寄せ/寄せない)・`rprior50`/`rprior100`(replay の prior)・`lr50`/`lr100`(学習モデル)・`lr50r2`(参考: 書き出しの prior と R2 の寄与を入れた学習モデル)。
- 点検: `cur` は #661 の `w50`(全体 847 点・賭け金 120,600・払戻 113,360・回収率 94.0%)と一致し、買い目の JSON もバイト単位で同じだった。計算し直せなかった行は全候補で 0。
- 対数損失・実際/見込み: 馬単位。「実際」は 3着内か(0/1)。取消・除外(`scratched`)と中止(着順なし)の馬は対象外。人気の帯は分析時点の単勝オッズの順位。
