# 組合せの確率の平たさを直す試算(Issue #661 段階 1)

本番のコード(`packages/core/src`・`cloud/src`)は変えていない。計算し直しの道具(`scripts/allocation-dataset.ts` の `replayRace`・`adjustProb`・`model`)と、このフォルダの `sharpen.ts` だけで比べた。

## 結論(決め方の規則を機械的に当てはめた結果)

**規則を満たす候補はなかった。実装しない。**

規則(試算の前に固定。Issue #661 の「やること 3」): 回収率が今の本番(w50)より悪くなく、見込み/実が今より 1 に近い候補のうち、変える量が一番小さいもの。判定は全体・全券種の合計で、点推定で行った。

- (1) 回収率が w50 の 94.0% 以上: 5 候補すべてが満たさなかった(78.2%〜84.3%)。
- (2) 見込み/実が w50 の 1.13 より 1 に近い: 5 候補すべてが満たさなかった(B25 は 1.13 で同じ、ほかは 1.19〜1.26)。

判定の表は末尾の「決め方の規則の適用」。

## τ = 1.6 は同じ書き出しに当てはめた値であること(結論の前に確認したこと)

Issue 本文の「最尤は τ = 1.6」は、本番の配分の書き出しから、1〜3 着の並びの尤度で当てはめた値で、評価に使う書き出しと同じデータから決めている。そのため、前半・後半で同じ向きかを見た。

| 区分 | w50 の回収率 | A16 の回収率 | 差 | A16 の見込み/実 | w50 の見込み/実 |
|---|---|---|---|---|---|
| 前半(265 レース) | 98.6% | 98.5% | −0.1pt | 1.15 | 1.07 |
| 後半(280 レース) | 92.6% | 77.2% | −15.5pt | 1.31 | 1.16 |

回収率の差は前半・後半とも 0 以下で向きは同じ。ただし改善の向きではない(前半はほぼ同じ、後半は 15.5pt 下がる)。見込み/実も前半・後半とも w50 より 1 から遠い。**τ = 1.6 が並びの尤度に合うことと、配分の回収率・見込み/実が良くなることは別で、後者は前半・後半のどちらでも確かめられなかった。**

## 材料と手順

- 材料: 本番の配分の書き出し(2026-10-27 時点、931 行)。配分の記録がある 545 行だけを使う(`noAllocation` 386 行は旧い分析で計算し直せない。`scripts/allocation-dataset.ts` の `replayableRows`)。中央 500・地方 45 レース。リポジトリには入れない。
- 計算し直せなかった行(route=invalid などで `replayedBets` が null)は、全候補で 0。A で本番モデルへ委ねたレース、B で元の確率で呼び直したレースも、全候補で 0(Issue 作成時の下調べにあった「w = 0 で当てはめが通らない 1 レース」は、この 545 行には出なかった)。
- 候補(結果を見る前に固定。`replay.ts` の `CANDIDATES`):
  - `w50`: 今の本番。補正後の 3着内率を w = 0.5 で市場に寄せる(本番の `shrinkTowardMarket` をそのまま import)。組合せの確率も同じ確率から作る。
  - `w100`: 寄せない(参考)。
  - `A12`・`A14`・`A16`: w50 のまま、組合せ・単勝の確率を作る Plackett–Luce の θ を τ = 1.2・1.4・1.6 乗する(`sharpen.ts` の `sharpenedPlModel`)。
  - `B25`・`B00`: 組合せ・単勝の確率だけ w = 0.25・0 で寄せた確率から作る(`substituteProbsModel`)。複勝の的中確率と EV は w = 0.5 のまま(本番の配分で、複勝の的中確率は補正後の 3着内率そのままで、同時分布のモデルを通らないため)。
- **単勝も候補で動く**: 本番では単勝の確率も組合せと同じ Plackett–Luce から作られ、モデルの口では分けられない。そのため Issue の「単勝・複勝は 0.5 寄せたまま」は「複勝は 0.5 寄せたまま」と読み替えた。参考に、単勝以外の券種だけの表も出した。決め方の判定は全券種の合計。
- 点検(結果を見る前に確かめた):
  - `w50` が #656 の `w50`(847 点・賭け金 120,600・払戻 113,360・回収率 94.0%)と一致した。
  - `w100` が #656 の `base`(828 点・賭け金 134,900・払戻 106,280・回収率 78.8%)と一致した。
  - 自作モデルを τ = 1 にした `A10`、確率の差し替えを w = 0.5 にした `B50` は、`w50` と買い目(券種・キー・賭け金)が 545 レースすべてで一致した(`replay.ts` に点検用として残してある)。
- 見込みの的中数 = 判定できた買い目(返還・判定不能を除く)の ev ÷ odds の合計。実的中数 = 的中の点数。「見込み/実」が 1 に近いほど、確率の見積もりが実際に合っている。
- 回収率の 95% 区間 = レース単位のブートストラップ(2,000 回・種は固定)。「上位 N 除」= 払戻の大きい順に N 点を、賭け金ごと除いた回収率。差の区間は基準(w50)との対ブートストラップ。**どの候補も差の区間は 0 をまたぐ**(= 回収率が w50 より下がったと断定はできない。規則は点推定で判定する決まりだった)。
- 前半・後半: 開催日でレース数がほぼ半々になる境目(同じ日は同じ側)。前半は 20260903〜20261001 の 265 レース、後半は 20261003〜20261025 の 280 レース。
- 再現(リポジトリのルートから。1 候補あたり約 1〜2 分): `pnpm tsx docs/investigations/combo-sharpen-661/replay.ts <書き出し> <出力先> <id>` を `w50 w100 A12 A14 A16 B25 B00`(と点検用 `A10 B50`)で流し、`pnpm tsx docs/investigations/combo-sharpen-661/report.ts <書き出し> <出力先> w50 w100 A12 A14 A16 B25 B00` で下の表を出す。純粋な部分のテストは `scripts/test/combo-sharpen-661.test.ts`。

## 読み取れること(表の数字から)

- **A(尖らせる)**: 点数と賭け金が増える(w50 の 847 点・120,600 円に対し A16 は 1,422 点・306,700 円で、賭け金は約 2.5 倍)。回収率は 78.2%〜83.5%、見込み/実は 1.19〜1.26 で、どちらも w50(94.0%・1.13)より悪い。人気の帯では 7 番人気〜の回収率が上がる(w50 71.3% → A16 109.6%)が、4〜6 番人気は下がる(108.4% → 73.5%)。
- **B25**: 点数・賭け金は w50 に近い(856 点・114,200 円)。見込み/実は 1.13 で w50 と同じ、回収率は 84.3%。単勝以外だけで見ると見込み/実は 1.05(w50 は 1.03)。
- **B00**: 点数が増え(943 点)、見込み/実は 1.25、回収率は 79.6%。単勝の点数が 318 → 23 に減る。
- **人気薄・高配当への影響**: 7 番人気〜を含む買い目の点数は、w50 の 352 に対し A が 342〜345、B25 が 335、B00 が 283 で、候補で大きく減ってはいない。1 点の払戻が賭け金の 20 倍以上の的中は、w50 が 8 点(払戻の 32.3%)、A が 4〜5 点(7.7%〜14.3%)、B25・B00 が 7 点(23.2%・17.0%)。1 点で払戻 1 万円以上の的中は w100 の 1 点だけで、この基準は比較に使えなかった(20 倍以上の見方は結果を見たあとに足したもの)。
- 地方は 45 レースで、買い目が 51〜101 点しかなく、数字に意味を読まない。
