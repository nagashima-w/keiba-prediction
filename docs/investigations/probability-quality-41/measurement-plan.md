## 1. 何を測るか

**prior の質**であって、**ツール全体の確率の質ではない**(ユーザー判断 2026-10-01:
実 Claude API は課金のため使わない。LLM 補正〈prior ± 0.10〉を含めた測定は、この結果を見たうえで
改めて相談する)。`runAnalysis` を `deps.analyze: null` で実行し、`priorSource: "prior-only"` とする。
LLM を使った場合の確率の質について、この測定は何も述べない。

- **事象**: 「3着以内に入る」。prior の合計目標は `min(3, 頭数)`(`scorer/prior.ts`)で、検証画面の
  `placeMaxRank=3` と同じ。同着で3着以内が4頭以上になる場合は全員を 1 とする(着順の数値 ≤ 3)。
- **観測の単位**: 出走した馬1頭 = 1観測(予測確率 = prior、結果 = 3着以内か)。
- **市場との比較は出走8頭以上のレースに限る**: 複勝の払戻対象は 8頭以上で3着まで、5〜7頭は2着まで、
  4頭以下は発売なし(`resolvePlaceBetTarget`)。複勝オッズ下限を Σ=3 に正規化した市場含意確率は、
  8頭以上でしか「3着以内」と同じ事象を表さない。**頭数は取消・除外を除いた出走頭数**で数える。
  モデル単独の Brier・分解は全レースで出す。
- **市場確率**: 確定の複勝オッズ**下限** `1/placeOddsMin` を Σ=3 に正規化した近似
  (主表)。複勝オッズは幅を持つ券種で、下限は単一の真値ではない。感度として下限と上限の**中点**
  `(oddsMin+oddsMax)/2` 版も並べる(追加リクエストなし)。

## 2. 選定ルール(レース単位ではなく開催日単位)

レース単位で選ぶと恣意が入るため、開催日の全レースを取る。**選定は取得時点の一覧
(`race_list_sub`)に機械的に適用する。** 帯広(ばんえい。場コード65)は `parseRaceId` が拒否するため
一覧のパース段階で自動的に除外される(選定対象外)。場コードは race_id の5〜6桁目。

### 2.1 中央

2026-09-26(土)と 2026-09-27(日)の**各日**について:

1. その日の中央一覧(`raceListSubUrl`)で、**場コードが最小の会場の全レース**を対象にする。
2. その日に中央開催が無い(一覧が空)なら、**1週前の同じ曜日**へ遡る。遡りは最大4週まで
   (それでも無ければ取得を止めて報告する)。遡った場合は、実際に使った開催日を `manifest.json` に残す。

### 2.2 地方

2026-09-30(水)について:

1. その日の地方一覧(`narRaceListSubUrl`)で、**場コードが最小の会場の全レース**を対象にする。
2. 対象が **10レース未満**なら、同じ日の**次に小さい場コードの会場の全レース**を加える。
   合計が10以上になるまで続ける。
3. その日に地方開催が無ければ**前日**へ遡る(最大7日まで。それでも無ければ止めて報告する)。

### 2.3 規模の見込み(リポジトリ内の保存済み一覧と実装からの見積もり。実測ではない)

中央 2日×12R、地方 10R 以上。1レースあたりのリクエストは 中央 = 頭数+4(出馬表1・戦績は馬ごと1・
調教1・オッズ1・結果1)、地方 = 頭数+3(調教なし)。全体で約 600〜620 リクエスト、間隔 2秒で約 21〜25 分。

## 3. 観測の規則

### 3.1 着順の分類(結果ページ `result.html` の着順欄から)

| 結果ページの着順 | 扱い |
|---|---|
| 数値(降着〈例 `5(降)`〉は確定した着順の数値) | 3以下なら 1(3着以内)、4以上なら 0。同着は数値どおり(3着が2頭なら両方 1) |
| `取消`・`除外` | **観測から除く**(出走していない) |
| `中止`・`失格` | **0(3着以内でない)として残す**(出走した) |
| 上のどれにも当たらない文言・着順欄が空 | **そのレースを観測から外す**(0/1 へ勝手に割り振らない)。**観測 JSON は保存せず**、理由と文言を実行記録に残して次のレースへ進む(§3.3) |

(検証画面は非数値の着順を集計対象外とするが、本測定は `中止`・`失格` を 0 として残す点で
**検証画面とは意図的に定義が異なる**。)

### 3.2 取消・除外の馬は prior を計算する前に除く

**結果を先に取り**、`取消`・`除外` の馬を `runAnalysis` に渡す出走馬(`RaceData.horses`)から除く。
出走確定頭数で prior(`fieldSize`・Σ=min(3,頭数))・市場含意確率・「8頭以上」の判定を揃えるため。
取消は発走前に確定する情報であり、リークではない。出馬表に取消馬が残っていない場合は何もしない。
結果にいるが出馬表にいない馬(または出馬表にいるが結果にいない馬)がある場合は、
**そのレースを観測から外す**(馬の対応が取れない)。

### 3.3 レース単位の除外(いずれも記録して次のレースへ。全体は止めない)

観測 JSON として**保存する**除外(決定的で、取り直しても変わらないもの):

- 結果が未確定(`RaceResultNotConfirmedError`)・結果ページの構造異常
- 3着以内の馬が0頭・出走頭数が3頭未満・出馬表と結果の馬が対応しない
- `runAnalysis` の例外(障害戦も他と同様に扱い、除外しない。例外が出たら除外)
- 分析日が近似になった(`dateApproximate=true`。`kaisaiDate` を必ず渡すため通常は起きない)

**観測 JSON として保存しない**(`manifest.json` の実行記録に raceId・理由・文言を残し、**再実行で取り直す**):

- **取得の失敗**(結果ページ・出馬表・オッズ等。一時的でありうる)。
- **§3.1 の「どれにも当たらない着順」**。着順欄の実際の表記はリポジトリ内に根拠が無い(保存済みの
  フィクスチャに非数値の着順は0件)。表記の違いで取消馬のいるレースが全部除外され、しかも二度と
  取り直せなくなるのを避けるため、保存せずに manifest へ文言を残し、人が確認してから扱いを決める
  (許可リストを変えるときは、この文書の「取得後の追記」に日付つきで残す)。
- **取得の停止(§4)の引き金になった呼び出しのレース**。停止はレースの除外ではなく取得全体の停止であり、
  元の失敗が「取得の失敗」に変換されていても保存しない。

**除外したレース(保存したもの・しなかったもの)の件数と理由はレポートに必ず載せる。**

### 3.4 戦績の取得に失敗した馬

馬の戦績取得が失敗した場合(5xx のリトライ後など)、その馬は戦績0走のまま prior が計算される。
**レースは除外せず**観測に警告を残す。主表は全レース、**感度として「戦績取得失敗の馬を含むレースを
除いた」集計を別掲**する。

### 3.5 オッズの状態

- 中央: `oddsStatus === "result"`(確定)のレースだけ市場比較に使う。`middle`・`yoso` のレースは
  モデル単独にだけ入れ、市場比較から外す(件数を出す)。
- 地方: オッズページ単体では確定と発売中を区別できず、`parseNarOdds` は常に `middle` を返す。
  地方で `yoso`(複勝なし)のレースは市場比較から外す。レースの終了は結果ページの存在(着順が確定済み)で確かめる。取得は 2026-10-01 で、対象の地方レースは
  2026-09-30 の開催のため、確定後のオッズと見なすが、**ページ上の確認はできない**(レポートに明記する)。
- 市場含意確率が作れないレース(複勝オッズが1頭でも欠損・不正)・**1を超える馬がいるレース**は、
  黙ってクリップせず、**モデル側・市場側とも市場比較から外す**(同じレース集合の対で比べる)。
  件数と ID をレポートに出す。

## 4. 取得手順と安全装置

- HTTP は `HttpClient`(`minIntervalMs: 2000`。**2秒以上**。自前の sleep は持たない)を**1個だけ**使う。
- **HTTP 400・403・429 が連続2回で取得を止める**(成功で連続回数を0に戻す。netkeiba への負荷を
  抑えるため、400 以外のブロックの兆候も数える)。止めたら以後はネットワークを叩かず
  即座に失敗させ、保存済みの観測だけを残して報告する(終了コードは非0)。`scrapeRace` は馬ごとの戦績の例外を警告に
  握りつぶすため、`scrapeRace` の外側で例外を待つのではなく、フェッチャを包んで数える。
- 1レースごとに**観測 JSON をその場で保存**する。再実行時は保存済みのレースを飛ばす
  (中断しても同じレースを取り直さない)。§3.3 の「保存しない」レースは、保存されていないので
  再実行で取り直される。
- raw の `RaceData`・結果ページ HTML は、リポジトリの外(スクラッチ領域)に保存する。
  **コンテナが消えれば失われる**(観測 JSON はコミットする)。prior はこの観測 JSON に保存した値を使う。
- **計画の文書がコミット済みでなければ、取得スクリプトは起動時に失敗する**(`git ls-files`・
  `git status` で確認。取得をこの文書のコミットより後にすることをコードで強制する)。同様に、
  取得に使うコード(`scripts/probability-quality-41`・`packages/core/src`・`packages/app/src`。
  `runAnalysis` が測定の本体のため app も含む)に未コミットの変更が
  あっても失敗する(取得に使った版を履歴に残す)。
- 実行の記録は `manifest.json`(`runs` に再実行ごとの記録を追記。選定した開催日・会場・レース ID、
  処理結果、停止の有無、フェッチャへ渡した要求数、ブロックの兆候〈400・403・429〉を受けた URL、
  実行時の git commit hash〈`git rev-parse HEAD`〉)。
- 計測には必ず実レース日の `kaisaiDate` を渡す(`dateApproximate=false`。`docs/current-spec.md` 9節)。
  リーク遮断は `runAnalysis` が自分で行う(#39)。計測側でも `filterRaceDataBefore` の診断値を
  `conditions`(`cutoffDate`・`removedResultCount`)に残す。この診断値は**計測側が生の戦績に
  掛けた値**で、`runAnalysis` が(自レースの走を先に除いてから日付で絞るため)内部で除いた件数とは
  内訳が一致しない場合がある。

## 5. 指標(取得前に固定する)

すべて `packages/core/src/ev/probability-quality.ts` の `buildBrierQualityReport`・
`buildProbabilityQualityReport` から出す。中央・地方は**別々に**集計する(混ぜない)。

### 5.1 確率の質(着順が必要。Go/No-Go の判断材料)

- **Brier スコア**と **Murphy 分解**(reliability / resolution / uncertainty)。帯は検証画面の
  キャリブレーションと同じ10帯(`calibration-bins.ts` を共有)。帯で丸めた分解は
  `BS = REL − RES + UNC` が近似でしか成り立たないため、残差(帯内分散 − 2×帯内共分散)も出す。
- **気候値に対する skill** `1 − BS/UNC`(全体の発生率を全馬に当てる予測との比較)。
- **対市場の Brier skill** `1 − BS_model / BS_market`(出走8頭以上・§3.5 の条件を満たすレースの
  同じ集合の対。主表=下限版、感度=中点版)。
- **BS 差(model − market)の95%区間**: **レース単位**の復元抽出ブートストラップ
  (馬は同一レース内で Σ=3 の制約により独立でないため、レースを再標本単位にする)。
  **反復回数 10000・シード 20261001**(パーセンタイル法 2.5% / 97.5%)。
- **resolution の参照値(null)**: 各レース内で結果の割り当てを並べ替える(各レースの3着以内の頭数は
  保つ)**レース内ラベル並べ替え**を **1000 回・シード 20261001** 行い、resolution の平均と
  95パーセンタイルを出す。小標本では識別力が無くても resolution は正に偏るため、「0に近いか」を
  この参照値と並べて読む。頭数による3着以内の確率の違い(`3/頭数`)はこの参照値にも含まれる
  (並べ替えが保つため)ので、**参照値を超える部分がレース内の識別力**に当たる。

### 5.2 #40 の指標のレース別の中央値とレンジ

レース別に `buildProbabilityQualityReport` を呼び、Spearman ρ・sd 比・max/min 比(モデル/市場)・
三連複同時分布の正規化 KL(モデル/市場)の**中央値とレンジ(最小〜最大)**を出す(算出不能のレースの
件数も併記)。市場側が関わる指標(ρ・sd 比・max/min 比の市場側・KL の市場側)は、
§1 の理由で**出走8頭以上かつ確定オッズ(§3.5)のレース**だけで出す。モデル単独の指標は全レース。
**三連複の全点等額購入 EV ÷ 払戻率は今回測定しない**(組合せオッズの追加取得が必要で、
Go/No-Go の Brier とは無関係なため。三連複オッズは取得しない)。

### 5.3 読み方(閾値は置かない)

- **識別力**: モデルの resolution が §5.1 の null の95パーセンタイルを超えるか、超えないか。
  超えないなら「この標本では、識別力を並べ替えと区別できない」。超える場合も大きさは
  市場の resolution(同じ集合)との比で読む。
- **対市場**: BS 差の95%区間が 0 を含むか。含むなら「この標本では市場との差を区別できない」。
- n はレース数で中央 24 レース前後・地方 10 レース前後(馬は約 360・約 110)。**断定しない**。
  各セルの下位桁に意味を読まない(10帯の各帯は数件〜数十件で、reliability・resolution は
  小標本で偏る)。
- 結論を「#35-2 に進む/進まない」と書く場合も、**LLM を使っていない prior だけの結果**であることと、
  上記の限界を併記する。

## 6. リーク経路の扱い(レポートに一覧を出す。取得後に更新しうるのは下の「残る」側の発見のみ)

- 遮断したもの: 戦績の自レースの走・施行日以降の走(#39。`runAnalysis` が遮断)。
- 本測定では無関係なもの: LLM プロンプト側の先読み(同日傾向・重賞の過去結果)は、LLM を使わないため無関係。
- 経路が存在しないもの: 騎手コース成績(`jockeyCourseStats` は production の `runAnalysis` から渡されない)、
  オッズ(prior は使わない。比較対象の市場は確定オッズで、これは事後情報だが予測の入力ではない)。
- 遮断できず残るもの(取得後に確かめ、レポートに記す): 馬場状態・馬体重増減・騎手・斤量は
  **取得時点(発走後)の値**であり、発走前の値と異なる可能性がある。

pnpm tsx scripts/probability-quality-41/fetch.ts --raw-dir <リポジトリ外の保存先>   # ネットワーク
