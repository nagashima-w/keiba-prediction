# 地方の締切直前の再計算(Issue #379〈#335-N〉)の調査記録

2026-10-19 の実測と、コードの調査。**事実と限界を分けて書く**(推測で埋めない)。実装の仕様は `docs/current-spec.md` の「締切の直前の再計算」。

## 1. 地方の締切は発走の何分前か → **分からない**

- netkeiba の地方のページには、締切・発売終了の表示も時刻もない。
  - フィクスチャ全件の grep(`grep -l "締切\|締め切\|発売終了\|投票締" fixtures/*`)は 0 件。
  - 実ページ(`nar.netkeiba.com/odds/index.html?type=b1`・`race/shutuba.html`)を全文で読んだ。時刻は `RaceData01` の「HH:MM発走」だけ。
  - 同ページが読む JS(`odds_common.js`・`odds_tanfuku.js`。`cdnv2.netkeiba.com`)にも、締切の処理はない。`ajax_get_odds.html?func=check` は枠連・b9 のタブの有無の確認で、締切とは無関係。
  - 地方のオッズのページには時刻が無い(`parseNarOdds` の JSDoc。`officialDatetime` は常に null)。
- 中央の締切も、同じ理由で分からない(今日 2026-10-19 は中央が開催なしで、観測できなかった)。
- **ユーザー決定(2026-10-19)**: 直前の回は、中央と同じ暫定の**発走 2 分前**のままにする。

### 実測: オッズの表示が止まる時刻(**締切ではない**)

単勝・複勝のページを発走の前後で連続して取得し、HTML を比べた。

| レース | 間隔 | 結果 |
|---|---|---|
| 盛岡 1R(`202635101901`、発走 11:35、9 頭) | 60 秒 | 11:34:30 と 11:35:30 で値が大きく違い、11:35:30 と 11:37:00 は完全に同一(md5 一致)。最後の更新は発走の前後 30 秒の間 |
| 盛岡 2R(`202635101902`、発走 12:10、10 頭) | 15 秒 | 値は 30 秒周期で更新。最後の更新は 12:10:00〜12:10:15 の間(発走の 0〜15 秒後)。12:10:15 と 12:10:30 は同一 |
| 浦和 1R(`202642101901`、発走 12:20、8 頭) | 15 秒 | 最後の更新は 12:20:00〜12:20:15 の間(発走の 0〜15 秒後)。12:20:15 と 12:20:30 は同一 |

- 3 レース(2 場)とも、**表示は発走の約 15 秒後まで動いた**。
- **これは表示の更新であって、発売の締切ではない。** 表示に遅れがあれば、締切が 2 分前でも説明でき、逆に締切が発走直前でも説明できる。どちらかは決められない。
- 限界: 盛岡 2 レースと浦和 1 レースだけ。名古屋・金沢・帯広・高知など他の場は未確認(金沢 1R も観測する予定だったが、待ち時間が長いので中止した=金沢には 1 本もリクエストしていない)。

### 実測: 最後のオッズからの距離(逸話であって統計ではない)

馬ごとの `|最終 / その時刻の値 − 1|` の、単勝オッズの中央値と最大。`N` は頭数。

| レース | 時点 | 中央値 | 最大 |
|---|---|---|---|
| 盛岡 1R(`N`=9) | 発走 3:30 前 | 48% | 81% |
| 同上 | 2:30 前 | 45% | 76% |
| 同上 | 1:30 前 | 45% | 78% |
| 同上 | 0:30 前 | 20% | 44% |
| 盛岡 2R(`N`=10) | 3:00 前 | 32% | 105% |
| 同上 | 2:00 前 | 37% | 101% |
| 同上 | 1:00 前 | 36% | 84% |
| 浦和 1R(`N`=8) | 1:30 前 | 11.4% | 24.2% |
| 同上 | 1:00 前 | 1.1% | 4.2% |

- 動きは**最後の 1 分に集中**している。盛岡の穴馬は 2 分前の値の約 2 倍になった(盛岡 2R の 5 番は 100.2 → 201.0)。浦和は売上が多いためか、ほとんど動かない。
- 「地方の、売上の小さいレースで変動が大きい」という見立てと整合する。ただし 2 レースだけで、**5 分前と 2 分前の差は、この観測では読み取れない**(どちらも最終値からの距離が近い)。
- 再現: 取得した HTML から、表の抽出は `<td class="Waku\d">\d+</td>\s*<td>(\d+)</td>.*?<span class="Odds ">([^<]*)</span>` で単勝(`id = "odds_tan_block"`)と複勝(`id = "odds_fuku_block"`)を読み、馬ごとに最終との比を取る。

### 発走時刻のずれ(スコープ外として記録)

- 地方一覧の発走時刻を 11:29 と 11:50 の 2 回取り、全 59 レースを比べたところ、差は 0 だった(約 20 分の窓。弱い反証)。
- リポジトリには発走時刻の変更への追従がない。再計算は、分析の保存時の発走時刻(`start_ms`)で固定している。
- 地方のオッズのページ自体が「HH:MM発走」を持つので、取り直しのたびに現在の発走時刻を読む、という後続の課題にできる。**今回はスコープ外。**

## 2. 取り直しの経路

- `scrapeRace` は、地方のとき `narOddsPageUrl`(`odds/index.html?type=b1`)を `parseNarOdds` で読む。`ODDS_URL_PATTERN`(`/odds/`)が地方の URL に当たる(`cloud/test/odds-url-pattern.test.ts`)。
- 組合せが OFF の地方は、この 1 本の取り直しで中央の OFF と同じ形になる。
- **組合せが ON の地方は、組合せを取りに行かない**(部分的な取り直し)。地方の組合せは次の取得のページで、リクエストが多い。
  - ワイド(b5)・馬連(b4)・馬単(b6)・枠連(b3): 各 1 ページ。
  - 三連複(b7): 軸馬別(`deriveNarTrioAxisUmabans` の軸ごとに 1 ページ)。
  - 三連単(b8): Issue #283(2026-10-13)から、軸(1 着固定)ごとに全頭分(`deriveNarTrifectaAxisUmabans`)。**2026-09-27 の「地方の三連単は取得しない」は旧い決定で、#283 で覆っている。**
- 分析時の組合せは DO の `fetch_cache` に残っている(保持 26 時間。計算ステップも同じキャッシュから読む)。取り直しはそこから、期間 `[comboFromMs, comboToMs]` の範囲のエントリだけ読む。

### 同じ URL を `fetch_cache` に書く経路(上の期間の上限の根拠)

`grep -n "networkFetcher" cloud/src/race-day-core.ts` の使用箇所(実装時に網羅した):

| 箇所 | 書くキー |
|---|---|
| 一覧(`fetchRaceList`) | 一覧のページ |
| 朝の取得(`runFetch`。`includeComboOdds: false`) | 出馬表・戦績・単勝複勝(組合せは書かない) |
| 発走前の取得(`runPreRaceFetch`) | 単勝複勝・**組合せ**(三連単の軸以外) |
| 重賞の過去10年(`prefetchGradeWinner`) | 過去10年のページ |
| 地方三連単の軸の取得(`runNarTrifectaStep`) | **三連単の軸のページ** |
| 中央の再計算(`closeFetcher`、`comboWindow` なし) | 単勝複勝・**組合せ**(中央だけ) |

- 組合せのキーを書くのは、発走前の取得・地方三連単の軸の取得・中央の再計算の 3 つ。手動の分析・一括の分析は、同じ朝・発走前のタスクを積むだけで、別の書き込み経路を持たない。
- 同じレースの発走前の分析をあらためて予約すると、そのレースの再計算の行と入力は消える(古い実行の再計算は起きない)。
- 後から別の取得(たとえば同じレースの発走前の分析を、再計算の前にやり直した結果)が組合せのキーを上書きしうるので、**分析の保存より新しいエントリは使わない**(上限)。取得ステップの開始より古いエントリも使わない(下限。前の実行の残り)。

## 3. スコープ外として記録するもの

- 発走時刻の変更への追従(上記)。
- 自分の購入でオッズが下がる影響の計算(売上の小さいレースで問題になる。別の課題)。
- 地方の組合せの取り直し(三連複・三連単は軸ごとに取るので本数が多い)。やるなら、組合せの扱い(`closeComboBasis`)を保存する、追加のみの列が要る(`analysis-close.ts` の JSDoc)。
- 自動の分析の対象(地方は交流重賞〈Jpn〉だけ)の拡大。Jpn 以外の地方のレースで再計算が効くのは、手動で分析したときだけ。
